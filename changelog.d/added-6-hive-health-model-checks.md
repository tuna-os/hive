- **The `hive-health` probe now reports model drift, so a new model stops depending on a human noticing** ([#6](https://github.com/tuna-os/hive/issues/6)). The tier table a Hive picks agent models from is refreshed by a job that needs a third-party benchmark API key; without one it does nothing, silently, and the fleet keeps running whatever was written down months ago. The probe's session tier now also reads `GET /api/config/backends` — the Hive's own per-backend discovery, no extra key — and adds three checks: `model-discovery` warns when a backend agents actually run on served the built-in static list (discovery failed, so no table built on it can be current) or when the endpoint cannot be read; `model-new` reports, at `info`, the models a backend offers that it did not at the previous run, adopting nothing, because a model that reads as an upgrade can benchmark worse for agent work; and `model-drift/<agent>` warns when an agent's configured model is absent from its backend's live list on two consecutive runs — a renamed or retired model id, caught here instead of at that agent's next start. Lists that prove nothing are never diffed (a static fallback, an empty list, the inference backends this endpoint serves without a fallback flag), one sample is never enough for a drift warning, and separator or provider-prefix spelling differences (`claude-opus-4.6` vs `claude-opus-4-6`, `gpt-5` vs `openai/gpt-5`) do not count as drift. Each run's per-backend census travels in the JSON report, which is what the next run diffs against.
