- The open-PR pre-dispatch guard no longer hot-loops or fails open while the GitHub installation is rate-limited. A rate-limited open-PR listing (primary `RateLimitError` or secondary `AbuseRateLimitError`) is now remembered per repo until the limit resets (`Rate.Reset` / `Retry-After`, capped at an hour, one minute when unknown) and replayed without a GitHub call, warned about once per repo per window instead of once per candidate — one hive logged 47,000 `could not list open PRs` warnings in an hour. While the listing is rate-limited the guard refuses the dispatch (dispatch reason `open-PR guard deferred: GitHub rate limit`, withheld reason `open_pr_guard_rate_limited`) instead of admitting issues an open PR may already link; other listing failures still fail open.
